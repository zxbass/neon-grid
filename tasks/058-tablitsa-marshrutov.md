## Часть 1 — Longest Prefix Match

Таблица маршрутов: пары `сеть/маска  next_hop`. Для каждого пакета с
адресом назначения выбери **самый длинный** префикс, который его
покрывает. При равенстве — меньший `next_hop`.

Вход:

```text
10.0.0.0/8     -> 1.1.1.1
10.1.0.0/16    -> 2.2.2.2
10.1.2.0/24    -> 3.3.3.3
0.0.0.0/0      -> 9.9.9.9

lookup: 10.1.2.44
lookup: 10.5.1.1
lookup: 8.8.8.8
```

### Выход

```text
10.1.2.44 -> 3.3.3.3
10.5.1.1  -> 1.1.1.1
8.8.8.8   -> 9.9.9.9
```

## Часть 2 — Forwarding-симуляция

Граф маршрутизаторов: каждый узел — пара «порт → next hop» (таблица,
как выше). Пакет отправляется из узла A в узел B: на каждом узле
выбирается next hop по LPM, пока пакет не достигнет узла с адресом,
равным B. Выведи полный путь и число хопов:

```text
PATH: R1 -> R4 -> R7 -> R12 (3 hops)
```

## Подсказки

- Маска: `(addr & mask) == (net & mask)`; `mask = (~0 << (32 - len)) & 0xFFFFFFFF`.
- LPM: сравнивай длины префиксов.
- Цикл маршрутов → `LOOP DETECTED` (лимит 64 хопа).
