# Миссия 112 — Банк «Каскад»

> Уровень: `★★★★☆` · Тема: транзакции, консистентность

Банк «Каскад»: транзакции, счета, движения. Джез впервые работает с деньгами Сетки и понимает, что деньги — это просто записи, которые кто-то ведёт.
— Деньги — это память, — Дон говорит серьёзно. — Память о том, кто кому должен.
Джез читает чужую память о долгах.

---

## Часть 1 — Переводы

Функция `transfer(from, to, amount)`: проверка баланса → списание →
начисление. Модель БД — общая мапа счетов в памяти.

Сымитируй гонку: 2 потока, каждый делает переводы между теми же
парами (например, 1000 раз по 1 кредиту A→B). Проверь инвариант:
`total = A + B` не меняется.

Покажи проблему без синхронизации:

```
RACE DETECTED: total=1999 (expected 2000)
```

## Часть 2 — Каскад

Исправь через **замок на все затронутые счета** (упорядоченный —
иначе deadlock!). Моделируй «каскадные переводы»: переводы между тремя
счетами в случайном порядке, с мьютексами на каждый счёт. Всегда
должен соблюдаться инвариант суммы.

Добавь журнал (как в 086): каждая транзакция пишется до применения.
При «откате» (обрыв питания) — восстанавливается последний
консистентный стейт.

```
LOCK ORDER: ok (no deadlock)
INVARIANT: total=3000 across 10000 tx
CRASH RECOVERY: restored to tx #9821 (19 rolled back)
```

## Подсказки

- Deadlock: A→B и B→A одновременно. Решение — всегда брать замки в
  порядке (сортировка адресов счетов).
- Журнал: пиши `BEGIN`/`COMMIT`; при обрыве — откат до последнего
  COMMIT.
- Инвариант проверяй после каждой операции и в конце.
