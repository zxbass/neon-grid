# Миссия 012 — PNG-заклинание

> Уровень: `★★★☆☆` · Тема: PNG, чанки, CRC32

Архив «Гаража» лопнул по швам: среди карточек с данными затесался битый PNG, который не открывается
ни у кого. Дон говорит, что файл пережил три перезаписи и два пожара, но один байт в нём всё же
сдался.
— Файл — это дом, — Прах прикладывает лупу к экрану. — Чини фундамент — и жильцы вернутся.
Джез читает чанки: длина, тип, контрольная сумма. Один чанк не сходится. И этот чанк — причина всей
беды.

---

## Часть 1 — Разбор чанков

Формат PNG: сигнатура `89 50 4E 47 0D 0A 1A 0A`, затем чанки:

| Поле | Размер |
| ------ | -------- |
| длина | u32 BE |
| тип | 4 байта ASCII |
| данные | длина байт |
| CRC | u32 BE (по типу + данным) |

Выведи все чанки:

```text
IHDR len=13 crc=OK
IDAT len=65536 crc=OK
IEND len=0   crc=OK
```

CRC считается как стандартный CRC-32 (полином `0xEDB88320`, та же
таблица, что в zlib/png), по полю «тип» + «данные».

## Часть 2 — Восстановление IHDR

В `IHDR` закодированы параметры изображения:

| Смещение в данных IHDR | Поле |
| -------- | ------ |
| 0 | ширина (u32 BE) |
| 4 | высота (u32 BE) |
| 8 | битовая глубина |
| 9 | тип цвета |
| 10 | метод сжатия |
| 11 | метод фильтрации |
| 12 | интерлейс |

Если CRC чанка не сошёлся — выведи `IHDR CORRUPT` и попробуй «починить»
чтиво: декодируй поля, считай новый CRC и выведи его (именно этот CRC
надо вписать, чтобы файл стал валидным).

### Выход

```text
IHDR CORRUPT
WIDTH=800 HEIGHT=600 DEPTH=8 COLOR=2 INTERLACE=0
FIXED_CRC: 0xFDD49A73
```

## Подсказки

- CRC32 в Python — `zlib.crc32`, в Go — `hash/crc32` (таблица IEEE).
- CRC считается от начала поля «тип», включая сам тип и данные.
- IEND — длина 0, тип `IEND`.
- Читай длину и CRC как big-endian.
