> Уровень: `★★★☆☆` · Тема: планировщики задач, приоритеты

Планировщик-пилот: задачи, дедлайны, приоритеты — и только одно ядро, которое всеми вертит. Джез
пишет планировщик и учится главному: не всё важное — срочное.

## Данные

`data/076/tasks.txt` — задачи: `id приоритет время_мс`. Все задачи
доступны в момент 0. Приоритет 1–10, чем больше — тем важнее.

## Часть 1 — FIFO и приоритет

`fifo`: строго по порядку файла. `prio`: по убыванию приоритета, при
равенстве — по порядку файла. Суммарное время — сумма времён задач:

```text
fifo: t1 t2 t3 t4 t5  total=140ms
prio: t3 t1 t5 t2 t4  total=140ms
```

## Часть 2 — Круговая очередь, W=2

Два воркера, квант 10 мс, событийная симуляция. Свободный воркер берёт
задачу из головы очереди; обычная задача исполняется один квант и, если
не завершилась, уходит в конец очереди; задача с приоритетом ≥ 7
исполняет два кванта подряд. Когда две задачи возвращаются в очередь
одновременно, первой добавляется задача воркера 0. Задержка — момент
завершения (поступление в 0). Выведи среднюю задержку (один знак после
запятой) и задержки в порядке файла:

```text
W=2 RR: avg_delay=64.0ms (t1=50 t2=80 t3=40 t4=70 t5=80)
```

## Подсказки

- Модель: очередь + два слота воркеров, время шагами по 10 мс.
- Событийная симуляция детерминирована: никаких `time.Sleep`.
- Задержка = `finish − arrival`, поступление всех задач — в 0.
