# Миссия 009 — Печать кузнеца

> Уровень: `★★☆☆☆` · Тема: контрольные суммы

Кузнец, который точит для «Гаража» навесные замки, попросил проверить новую пломбу: шесть байт данных, запечатанных контрольной суммой. Если печать сходится — груз настоящий, если нет — за пломбой кто-то уже лазил.
— Печать должна быть как характер, — говорит кузнец, вытирая руки ветошью. — Один раз проверенная — и видно, человек она или подделка.
Джез считает сумму, и железный ящик на верстаке тихо щёлкает замком.

---

## Часть 1 — Сумма в кольце

Алгоритм печати:

1. Начинай с `acc = 0x5A5A5A5A`.
2. Для каждого байта `b` файла: `acc = ((acc << 5) | (acc >> 27)) ^ b`.
   (поворот 32-битного слова влево на 5 с XOR байта)
3. Конечная печать — `acc & 0xFFFFFFFF`, выведи в hex.

Для файла с байтами `01 02 03` посчитай вручную:

- acc = 0x5A5A5A5A
- `<<5 | >>27` от 0x5A5A5A5A = 0xB4B4B4B5, XOR 0x01 → 0xB4B4B4B4
- … дальше сам.

### Выход

```
SEAL: 0xXXXXXXXX
```

## Часть 2 — Проверка партии

На вход — файл, где первые 4 байта — ожидаемая печать (u32 LE),
а остальное — груз. Проверь печать и выведи `SEAL OK` или `SEAL BAD`,
с фактической печатью в hex.

### Пример

```
SEAL BAD (expected 0xDEADBEEF, got 0x12345678)
```

## Подсказки

- Поворот влево: `(x << 5) | (x >> (32 - 5))`, но только если `x`
  беззнаковый 32-бит; в языках с фиксированной шириной (Go, Rust, C)
  используй `uint32`, иначе сдвиг `>>` будет арифметическим.
- В Python не забудь `& 0xFFFFFFFF` после каждого шага.
- В части 2 читай ожидаемую печать как LE.
