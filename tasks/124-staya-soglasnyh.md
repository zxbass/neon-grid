# Миссия 124 — Стая согласных

> Уровень: `★★★★★` · Тема: распределённый консенсус, выбор лидера

Стая согласных: консенсус в распределённой системе — договориться, когда никто не главный. Джез
учится тому, что решение может быть общим.
— Стая летит вместе, — Прах смотрит в потолок. — Но направление выбирают все — или никто.
Джез учится выбирать вместе.

---

## Данные

`data/124/cluster.log` — записанная история кластера из 3 узлов
(`node-1..node-3`). Строки:

- `VOTE <term> <from> <for>` — узел `from` голосует за узел `for`;
- `LEADER <term> <node>` — объявление лидера (для сверки);
- `HEART <term> <node> idx=<n>` — heartbeat лидера с индексом `n`;
- `LOGOK <term> <node> idx=<n>` — фолловер принял запись `n`;
- `COMMIT <term> <key>=<value>` — операция закоммичена в терме;
- `CATCHUP <term> <node> +<n> entries` — догон пропущенных записей.

## Часть 1 — Выбор лидера

Упрощённый Raft: лидером терма становится узел, набравший большинство
голосов (`>= 2` из 3) в этом терме. Подсчитай голоса по `VOTE`-строкам
и выведи лидеров в порядке термов.

### Выход

```text
TERM 1: leader=node-2
TERM 2: leader=node-1
```

## Часть 2 — Репликация журнала

Операция закоммичена, когда её приняло большинство: лидер (1) плюс
узлы, приславшие `LOGOK` за тот же терм. Для каждой `COMMIT`-строки
выведи `COMMIT <key>=<value> (<ack>/3)`, для каждой `CATCHUP`-строки —
догон.

### Выход

```text
COMMIT k=v (3/3)
COMMIT k2=v2 (2/3)
CATCHUP node-3 +3 entries
```

## Подсказки

- Голоса считай за каждый терм отдельно; термы идут по возрастанию.
- `LOGOK` узла засчитывается один раз, даже если строк несколько.
- Строки `LEADER` — для сверки: они совпадают с расчётом по голосам.
