# Миссия 080 — Логи на поток

> Уровень: `★★★☆☆` · Тема: параллельный парсинг логов

Логи на поток: миллионы строк, и в каждой — чья-то жизнь. Джез впервые обрабатывает поток, который
больше неё, и понимает, что читать — это тоже фильтровать.
— Лог — это исповедь системы, — CROW выдыхает дым. — Только исповедников много, а ушей мало.
Джез становится ушами.

---

## Часть 1 — Формат и парсер

Лог-строки:

```text
2049-12-01 03:14:15 10.0.0.7 USER crow ACTION login OK
2049-12-01 03:15:00 10.0.0.8 USER zen ACTION read file:plan.doc OK
2049-12-01 03:15:22 10.0.0.9 USER ghost ACTION sudo rm -rf / OK
```

Парсер: разбивает на поля, фильтрует события `ACTION`. Выведи
статистику по `USER` (имя → число действий) и топ-3:

```text
ACTIONS: crow:1 zen:1 ghost:1
TOP: ghost zen crow
```

## Часть 2 — Параллельный парсер

Разбей файл на `W` частей (по границе строк), парси каждую часть в
своём потоке, собери агрегаты через редукцию (локальные счётчики →
слияние). Без дублей и потерь.

Найди подозрительные события: `sudo` или `rm` или `delete`:

```text
SUSPICIOUS: 4
  crow:12:01 sudo rm -rf /
  ghost:... delete data:users.db
MERGE CHECK: parts=4 rows=1_000_000 matches_single=1_000_000
```

## Подсказки

- Граница разбиения: ищи `\n` рядом с `offset = i * size / W`.
- Локальные мапы на воркер, потом merge — нет гонок.
- Ключ подозрительности: `ACTION` содержит `sudo`/`rm`/`delete` (case-insensitive).
