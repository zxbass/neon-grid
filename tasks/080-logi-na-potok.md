# Миссия 080 — Логи на поток

> Уровень: `★★★☆☆` · Тема: параллельный парсинг логов

Логи на поток: миллионы строк, и в каждой — чья-то жизнь. Джез впервые обрабатывает поток, который
больше неё, и понимает, что читать — это тоже фильтровать.
— Лог — это исповедь системы, — CROW выдыхает дым. — Только исповедников много, а ушей мало.
Джез становится ушами.

---

## Данные

`data/080/access.log` — строки вида:

```text
2049-12-01 03:14:15 10.0.0.7 USER crow ACTION login OK
```

Поля: дата, время, IP, `USER`, имя, `ACTION`, текст действия, результат.

## Часть 1 — Формат и парсер

Посчитай действия по каждому пользователю: по убыванию числа, при
равенстве — по имени. Выведи все счётчики и топ-3:

```text
ACTIONS: crow:8 zen:6 ghost:5 reave:3 miko:2
TOP: crow zen ghost
```

## Часть 2 — Параллельный парсер

Файл режется на `W=4` части по границам строк; каждая часть парсится
отдельно, агрегаты сливаются. Подозрительное действие: текст действия
(без учёта результата) содержит `sudo`, `rm` или `delete` без учёта
регистра. Выведи число подозрительных, первые два примера и строку
сверки слияния с однопроходным подсчётом:

```text
SUSPICIOUS: 6
  ghost: sudo rm -rf /tmp/x
  reave: delete data:users.db
MERGE CHECK: parts=4 rows=24 matches_single=6
```

## Подсказки

- Граница разбиения: ищи `\n` рядом с `offset = i × size / W`.
- Локальные мапы на воркер, потом merge — нет гонок.
- `matches_single` — число подозрительных после слияния частей; оно
  должно совпасть с однопроходным подсчётом.
