# Миссия 107 — Декомпилятор VM

> Уровень: `★★★★★` · Тема: байткод VM, декомпиляция

Декомпилятор VM: виртуальная машина, которая выполняет байткод. Джез не просто исполняет код — она
объясняет его по-человечески.
— VM — это переводчик между машиной и человеком, — Зен кивает на байткод. — А ты — тот, кто
переводит обратно.
Джез переводит.

---

## Часть 1 — Байткод

VM «IronCore»: стековая, 1 байт на опкод:

| Опкод | Название |
| ------- | ---------- |
| 0x01 | PUSH imm32 (LE) |
| 0x02 | POP |
| 0x03 | DUP |
| 0x04 | ADD |
| 0x05 | SUB |
| 0x06 | MUL |
| 0x07 | AND |
| 0x08 | JMP rel8 |
| 0x09 | JZ rel8 (pop, если 0 — jump) |
| 0x0A | CMP (pop a, pop b, push b==a) |
| 0x0B | LOAD var (u16 — индекс) |
| 0x0C | STORE var (u16) |
| 0x0D | CALL func (u16) |
| 0x0E | RET |
| 0x0F | HLT |

Разбери файл `vm.bin` в «псевдокод»:

```text
0x0000: PUSH 10
0x0005: LOAD 0
0x0008: ADD
0x0009: STORE 0
0x000C: HLT
```

## Часть 2 — Восстановление логики

Выведи «высокоуровневый» код для переменных (STORE/LOAD — это
`x0, x1...`), сворачивая PUSH+LOAD и объединяя операторы:

```text
x0 = 10
x1 = x0 + x0
if x1 == 0 then jump 0x0030
...
call func(0x0001)
```

Цель — понять, что делает программа, и ответить: какое значение она
вычисляет для входных данных, если вход — переменная `x0` перед
выполнением? Выведи упрощённую формулу и результат для `x0 = 5`
(ровно две строки):

```text
x1 = 2*x0 + 3
RESULT(5) = 13
```

## Подсказки

- Декомпиляция: пройди поток, сопоставь опкоды с шаблонами
  (PUSH+LOAD → присваивание и т.д.).
- JMP/JZ усложняют поток — обрабатывай линейные участки, для веток
  используй граф потока управления.
- Если совсем тяжело — сначала «распрями» поток в блоки.
