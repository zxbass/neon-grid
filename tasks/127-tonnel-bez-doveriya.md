# Миссия 127 — Туннель без доверия

> Уровень: `★★★★★` · Тема: VPN-туннель, шифрование, доставка, порядок

Туннель без доверия: зашифрованный канал, который не верит ни одной из сторон. Джез строит тоннель,
в котором никто не знает, кто с кем говорит.
— Недоверие — тоже фундамент, — Прах кивает. — Иногда самый крепкий.
Джез строит на недоверии.

---

## Часть 1 — Пакеты

Формат пакета:

```text
magic 0x4A4B (u16) | seq (u32 BE) | flags (u8) | len (u16 BE) | payload | tag (u16)
```

- `payload` — данные фрагмента (≤ 1200 байт);
- `tag = crc16_ccitt(seq || flags || payload)` (CRC из 016);
- `flags`: бит 0 — последний фрагмент потока (FIN), бит 1 — первый (SYN).

Клиент читает stdin, режет по 1200, шлёт фрагменты, получает `ACK <seq>`
и повторяет при тайм-ауте 500 мс (как ARQ из 056). Собери поток обратно
на сервере, учитывая, что UDP может переставить порядок.

### Выход

```text
SENT 4 fragments (len=4096)
REASSEMBLED: 4096 bytes, order OK
```

## Часть 2 — Порядок и шифрование

UDP не гарантирует порядок — протокол должен. Введи окно приёма 32
фрагмента: принимай по `seq`, собирай в порядке, выдавай вверх только
непрерывный хвост (`next_seq`).

Добавь шифр: `payload` перед подписью XOR-ится ключом `0x55` (миссия
021), а `tag` считается **по открытому** payload. Порядок в заголовке
не шифруется.

Прогони канал с «перемешивателем» (тестовый сервер отдаёт фрагменты в
случайном порядке) и проверь roundtrip:

### Выход

```text
REORDERED: 4096 bytes in 4 fragments
TUNNEL OK (XOR+CRC verified)
```

## Подсказки

- Счётчик `seq` растёт глобально на поток; `next_seq` — окно решении.
- Tag считается по открытым данным, шифруется только payload — иначе
  приёмник не смог бы проверить подпись до расшифровки.
- Тайм-ауты и ретраи — переиспользуй окно из 056.
