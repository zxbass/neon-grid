# Миссия 102 — Мини-дизассемблер

> Уровень: `★★★★☆` · Тема: декодирование опкодов

Мини-дизассемблер: байты превращаются в инструкции, а инструкции — в рассказ о том, что делает
программа. Джез впервые читает чужой замысел по опкодам.
— Машинный код — это почерк, — Зен показывает на байты. — У каждой программы — свой.
Джез учится читать почерк.

---

## Часть 1 — Таблица команд

Формат инструкций (1–4 байта: опкод плюс операнды):

| Опкод | Длина | Формат | Мнемоника |
| ------- | -------- | -------- | ----------- |
| 0x00 | 1 | - | NOP |
| 0x01 | 2 | r | LDA #r (r — младшие 4 бита: регистр) |
| 0x02 | 3 | addr16 | JMP addr |
| 0x03 | 4 | r,addr16 | LD r, addr |
| 0x04 | 2 | r | INC r |
| 0x05 | 2 | r | DEC r |
| 0x06 | 1 | - | HLT |
| 0xFF | 1 | - | RET |

`r` — регистр (0=A, 1=B, 2=X, 3=Y), старшие 4 бита — флаги (игнорируй).

Диз ассемблируй файл `code.bin`:

```text
0x0000: NOP
0x0001: LDA #A
0x0003: LD B, 0x1234
...
0x0010: HLT
```

## Часть 2 — Сброс и поток

Известно: программа начинается с 0x0000 и заканчивается `HLT`.
Некоторые байты между инструкциями — данные (опкод `LD` читает 2 байта
адреса, `JMP` — тоже). Диз ассемблируй **строго** по длинам (не по 1 байту —
иначе разъедется), найди все `JMP`-цели, которые указывают внутрь
кода, и выведи их:

```text
ENTRY: 0x0000
JUMPS: 0x0012 0x0034 0x0056
END: 0x00A0
```

## Подсказки

- Читай опкод, по нему — длину, двигай указатель.
- Проверяй выход за границы: `TRUNCATED` у последней инструкции.
- `RET` без `JMP`-возврата — просто останови.
- Байты данных (не команды) не дизассемблируй — только по потоку.
