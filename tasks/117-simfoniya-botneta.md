# Миссия 117 — Симфония ботнета

> Уровень: `★★★★★` · Тема: координация ботнета, консенсус

Симфония ботнета: тысячи машин, которые играют по одной партитуре. Джез впервые управляет оркестром,
который не знает, что он оркестр.
— Оркестр звучит громче солиста, — Зен поднимает палец. — Но дирижёр у него один.
Джез становится дирижёром.

---

## Часть 1 — Выбор лидера

Симуляция: N узлов (процессы/потоки), каждый имеет id. Лидер — узел с
наименьшим id, который «жив» (отвечает на ping). Протокол простой:
каждый узел шлёт `LEADER <id>` соседям; узел с минимальным id
получает подтверждения.

Реализуй выбор лидера (нет центрального сервера!) и выведи:

```text
LEADER ELECTED: node 3 (confirmed by 8/8)
```

## Часть 2 — Двухфазный коммит

Запуск атаки — двухфазный коммит:

1. **prepare**: лидер шлёт `PREPARE <attack_id>` всем, узлы отвечают
   `YES`/`NO` (NO — если занят);
2. **commit**: если все `YES` — лидер шлёт `COMMIT`, все стартуют.

Если хоть один `NO` — `ABORT`, никто не стартует. Узлы отвечают `NO`
случайно (детерминированно по seed).

Выведи по трём раундам:

```text
ROUND 1: 9/10 YES -> COMMIT (started)
ROUND 2: 7/10 YES -> ABORT
ROUND 3: 10/10 YES -> COMMIT
```

## Подсказки

- Узлы = горутины с каналами; это симуляция, реальные сокеты не нужны.
- Лидер знает общее число узлов (входной параметр N).
- Таймаут на подтверждения (500 мс) — иначе зависнешь.
- После COMMIT каждый узел печатает `[node] GO` — все должны быть.
