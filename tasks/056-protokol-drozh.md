# Миссия 056 — Протокол «Дрожь»

> Уровень: `★★★★☆` · Тема: ARQ, повторные передачи, чек-суммы

Протокол «дрожь»: передача по ненадёжным каналам, где пакеты теряются, дублируются и приходят
вразнобой. Джез разбирает записи протокола, который не боится дрожи.
— Надёжность — это не про железо, — Зен поправляет провод наушника. — Это про то, как ты
договариваешься с тем, что дрожит.
Джез достаёт из дрожащего лога целые сообщения и считает, сколько раз каналу пришлось повторить.

---

## Данные

Файлы `data/056/window1.bin` и `data/056/window4.bin` — записи
передачи. Каждый кадр:

```text
0x5A | seq(1) | 8 байт данных | crc16(2 байта, BE)
```

`crc16` — тот же CRC-CCITT (полином 0x1021, init 0xFFFF, без xorout),
что в миссии 016. Битый кадр — кадр с неверной чексуммой (канал
испортил crc).

## Часть 1 — Повтор передачи

Прочитай `window1.bin` и проиграй сессию: для каждого кадра проверь
чексумму. Совпала — `ACK <seq>`; не совпала — `NAK <seq>`; при
повторной передаче того же seq (после NAK) — `ACK <seq> (retry N)`,
где N — сколько раз этот seq уже получал NAK. В конце — суммарный
объём уникальных данных.

### Выход

```text
SEQ 0 ACK
SEQ 1 NAK
SEQ 1 ACK (retry 2)
SEQ 2 ACK
DONE: 24 bytes
```

## Часть 2 — Окно

Ретрансмиссия — кадр, чей `seq` уже встречался в этом файле ранее.
Посчитай ретрансмиссии в каждом файле (окно 1 и окно 4).

### Выход

```text
WINDOW=1 retries=2
WINDOW=4 retries=1
```

## Подсказки

- CRC-CCITT параметры зафиксируй в одной функции, используй везде.
- Первое появление seq — не ретрансмиссия, все следующие — да.
- Битый кадр проверяется только чексуммой; данные не «чинятся».
