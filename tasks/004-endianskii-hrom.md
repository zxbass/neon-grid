# Миссия 004 — Эндианский хром

> Уровень: `★☆☆☆☆` · Тема: порядок байт (endianness)

Омега-Дайн перешла на новую партию контроллеров, и вся периферия в «Гараже» вдруг начала читать
числа наоборот. Кто-то в цеху перепутал порядок байтов, и теперь у каждого устройства свой акцент.

## Часть 1 — Разворот чисел

Входной бинарный файл содержит последовательность 32-битных целых
чисел в **little-endian** (младший байт первый). Прочитай их и выведи
как десятичные значения. Для каждого числа также выведи его
**big-endian** представление в hex (старший байт первый).

Файл `nums.bin`:

```text
41 00 00 00   01 00 00 00   00 00 00 00   ...
```

Первый байт `0x41` — младший → число `0x00000041 == 65`.

### Выход

```text
value=65    BE=0x00000041
value=1     BE=0x00000001
```

### Входные данные

Бинарный файл, длина кратна 4.

## Часть 2 — Подпись

Некоторые числа хранят **подпись узла** как строку из 4 символов в
открытом виде, но её положили в 32-битное слово задом наперёд.
Например, `4f 4d 45 47` (LE-слово `0x47454d4f`) читается как `OMEG`.
Пройди по файлу, и для каждого слова, где все 4 байта — печатные ASCII,
выведи символы в обратном порядке как строку.

### Пример

```text
0x47454D4F -> GEMO
0x41445243 -> ADRC   (байты 43 52 44 41, развёрнуто: 41 44 52 43)
```

На самом деле: байты на диске `4f 4d 45 47` → LE-число
`0x47454d4f` → байты старшим-первым: `47 45 4d 4f` = `GEMO`.

## Подсказки

- LE-чтение: `b0 | b1<<8 | b2<<16 | b3<<24`.
- Для обратного порядка просто переставь байты местами.
- В большинстве языков есть встроенный `Endian.Big`/`Little` — но
  здесь полезно написать руками, чтобы понять, что происходит.
