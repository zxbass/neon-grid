# Миссия 044 — DNS-душа

> Уровень: `★★★☆☆` · Тема: DNS-запрос, бинарный протокол

DNS — телефонный справочник Сетки: имя превращается в адрес. Когда справочник врёт, все звонят не
туда.
— Имя — это обещание, — CROW выдыхает дым в потолок. — А обещания можно переписать.
Джез учится читать справочник и слышать, как в нём шелестят чужие правки.

---

## Данные

`data/044/reply.bin` — бинарный DNS-ответ (big-endian): заголовок
(12 байт), один вопрос `example.com A IN`, три записи в секции ANSWER.

## Часть 1 — Разбор ответа

Разбери пакет: выведи ID и RCODE (младшие 4 бита флагов), затем все
A-записи из ANSWER в порядке появления — имя (с точкой на конце) и
адрес:

### Выход

```text
ID=0x1234 RCODE=0
edge.example.net. -> 192.0.2.1
example.com. -> 93.184.216.34
```

## Часть 2 — Сжатие имён

Имена в ответе **сжаты** (указатель): 2 байта `0xC0 0xXX` — смещение в
пакете, откуда продолжить читать имя. Реализуй обход указателей
(с защитой от циклов) и выведи все записи ANSWER с их типом
(`CNAME`/`A`), включая адреса:

### Выход

```text
example.com. CNAME -> edge.example.net.
edge.example.net. A -> 192.0.2.1
example.com. A -> 93.184.216.34
```

## Подсказки

- Все числа — big-endian.
- Метка: 1 байт длина + байты; длина 0 — конец имени.
- Указатель: `0xC0 | 0x..`; следи за пределом в 255 прыжков.
- RR-заголовок: NAME(переменная) TYPE(2) CLASS(2) TTL(4) RDLENGTH(2) RDATA.
