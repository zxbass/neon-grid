# Миссия 005 — Шапка прошивки

> Уровень: `★☆☆☆☆` · Тема: заголовки бинарных форматов

Утром на пороге «Гаража» оставили плату управления вентиляцией с сорванной пломбой и подписью: «почините, а то у нас тут дышится по-другому». Внутри — прошивка с каталогом, контрольной суммой и клеймом версии.
— Прошивка — это документ, — Зен кладёт плату на стол. — Только написанный не чернилами, а шестнадцатеричными числами.
Джез учится читать такие документы. Один байт, другой — и железка начинает говорить.

---

## Часть 1 — Поля заголовка

Заголовок занимает ровно **64 байта**, поля идут в этом порядке:

| Смещение | Размер | Тип | Поле |
|----------|--------|-----|------|
| 0 | 4 | ascii | магия `FW` + 2 байта версии |
| 4 | 8 | ascii | название прошивки (до NUL) |
| 12 | 4 | u32 LE | размер кода |
| 16 | 4 | u32 LE | контрольная сумма |
| 20 | 2 | u16 LE | версия API |
| 22 | 2 | u16 LE | версия аппаратуры |
| 24 | 40 | ascii | описание (до NUL) |

Магия должна быть `FW` (0x46 0x57), иначе — `BAD_MAGIC`.

### Выход

```
magic    : FW v1.4
name     : omegadain-boot
code_len : 1048576
crc      : 0xDEADBEEF
api      : 3.2
hw       : 7.1
desc     : Primary bootloader rev 2
```

## Часть 2 — Валидация

Проверь, что контрольная сумма честная: посчитай сумму байт кода
(начиная с байта 64 и до `64 + code_len`) как 32-битные слова
little-endian, по модулю 0xFFFFFFFF. Если равна `crc` из заголовка —
выведи `CRC OK`, иначе `CRC MISMATCH` и ожидаемое/фактическое
значения в hex.

### Пример

```
CRC OK (0xDEADBEEF)
```

## Подсказки

- Строки до NUL: читай байты, собирай в строку, обрезай на первом `0x00`.
- `code_len` может быть больше реального размера файла — обрежь чтение
  по длине файла и отметь `TRUNCATED`, если так.
- Сумма по модулю `0xFFFFFFFF` — это не просто сумма без знака: убедись,
  что складываешь 32-битные значения и берёшь остаток от деления на
  0x100000000-1, что на практике означает обычное переполнение u32
  без знака.
