# Миссия 014 — Архив «Чёрного ящика»

> Уровень: `★★★☆☆` · Тема: кастомный архив, парсер

Курьер принёс «чёрный ящик» с одного из рейсов Омега-Дайн: контейнер с двумя файлами и таблицей, в которой у каждого файла своя контрольная сумма. Один файл в порядке, второй — нет.
— Упаковка не защищает, — Зен отодвигает ящик в сторону. — Защищает то, что ты знаешь, что внутри.
Джез распаковывает контейнер по записям каталога, и мир за окном «Гаража» на минуту становится тише.

---

## Часть 1 — Заголовок архива

Формат `BOX`:

| Поле | Размер |
|------|--------|
| магия | 4 (`BOXD`) |
| версия | u16 LE |
| число файлов | u16 LE |
| таблица: для каждого файла — имя (16 байт, до NUL), размер (u32 LE), CRC32 (u32 LE), смещение (u32 LE) | |

После таблицы — данные файлов по смещениям.

Выведи список файлов:

```
FLIGHT01.LOG   size=4096 crc=0xA1B2C3D4
AUDIO.CHUNK    size=88000 crc=0xDEADBEEF
```

## Часть 2 — Распаковка + проверка

Распакуй каждый файл в отдельный файл с его именем. После распаковки
проверь CRC32 каждого распакованного содержимого и выведи:

```
FLIGHT01.LOG: EXTRACTED (CRC OK)
AUDIO.CHUNK:  EXTRACTED (CRC MISMATCH)
```

Для файла с битым CRC выведи также ожидаемый и фактический CRC.

### Пример

```
FLIGHT01.LOG: EXTRACTED (CRC OK)
AUDIO.CHUNK:  EXTRACTED (CRC MISMATCH expected=0xDEADBEEF got=0x00112233)
```

## Подсказки

- Смещения могут быть относительными к началу файла — проверь, что
  `offset + size <= len(file)`.
- CRC32 — тот же IEEE, что в PNG.
- Имена могут быть короче 16 байт — обрезай по NUL.
- Если магия не `BOXD` — выведи `NOT_A_BOX` и выйди.
