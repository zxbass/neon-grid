# Миссия 011 — BMP-разведка

> Уровень: `★★☆☆☆` · Тема: BMP, чтение пикселей

Фотограф с нижних уровней продаёт снимки, которые «не проявились». В файлах — заголовки BMP, и, по слухам, за картинками спрятано больше, чем пиксели.
— Каждая картинка — это сначала числа, — говорит Крем, перебирая карты памяти. — Только потом она становится красивой.
Джез разбирает заголовок: ширина, высота, глубина — и учится видеть изображение до того, как оно появится.

---

## Часть 1 — Заголовок BMP

Разбери стандартный BMP (без сжатия, `BITMAPINFOHEADER`):

| Смещение | Поле |
|----------|------|
| 0 | `BM` — сигнатура |
| 18 | ширина (i32 LE) |
| 22 | высота (i32 LE) |
| 28 | бит на пиксель (u16 LE) |
| 34 | размер данных изображения (u32 LE) |

Выведи:

```
WIDTH=64 HEIGHT=32 BPP=8 DATA=2048
```

Поддержи только `BPP=8` (палитра) и `BPP=24` (RGB), иначе `UNSUPPORTED`.

## Часть 2 — Яркость в ASCII

- Для 24-бит: пиксель = B,G,R (в таком порядке на диске!).
- Для 8-бит: пиксель — индекс в палитре; палитра идёт сразу после
  заголовка: 256 записей по 4 байта (B,G,R,reserved).

Яркость = `(R*30 + G*59 + B*11) / 100`. Сопоставь с символами
`" .:-=+*#%@"` (10 уровней). Строки BMP хранятся **снизу вверх** —
переверни. Каждая строка дополнена до кратности 4 байт.

### Выход

```
@@@@%%%.....:====...
```

## Подсказки

- Высота может быть отрицательной — тогда строки уже идут сверху вниз
  (стандартное поведение многих конвертеров); учти это.
- Паддинг строки: `(width * bpp / 8 + 3) & ~3`.
- В 24-бит BGR порядок: `byte[0]=B, byte[1]=G, byte[2]=R`.
