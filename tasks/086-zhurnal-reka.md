# Миссия 086 — Журнал «Река»

> Уровень: `★★★☆☆` · Тема: журналирование, WAL

Журнал-река: WAL, записи транзакций, откаты. Джез читает журнал базы данных и видит историю, которую
база предпочла бы не рассказывать.
— Журнал — это дневник, — Зен говорит тихо. — А дневники пишут для того, чтобы их однажды прочитали.
Джез читает чужой дневник.

---

## Часть 1 — Чтение WAL

Журнал `wal.bin` — последовательность записей:

| Поле | Размер |
| ------ | -------- |
| magic | 2 (`0x4A4B` «JK») |
| len | u16 LE |
| crc16 | u16 LE (по данным) |
| данные | len байт |

Данные — операции `SET <key>=<value>` или `DEL <key>` (ASCII).
Пропусти битые записи (crc не сошёлся — «обрыв»), останови чтение на
первой битой (всё после — мусор).

Примени валидные операции к KV-стору и выведи состояние:

```text
WAL: 12 ok, 1 corrupted
FINAL: a=1 b=2 c=DELETED
```

## Часть 2 — Восстановление после краша

Симулируй краш: последняя запись записана наполовину (длина не
совпадает с концом файла). Программа должна:

1. прочитать все полные записи;
2. записать «хвост» обратно: сгенерировать контрольную точку —
   весь KV-стор в файл `snapshot.bin` (формат: `SNAP` + число пар + пары);
3. вывести, сколько записей было применено и сколько отброшено.

### Выход

```text
APPLIED: 12  SKIPPED: 1 (truncated tail)
SNAPSHOT: a=1 b=2 c=DELETED (3 entries)
```

## Подсказки

- CRC16 — из миссии 016 (CCITT 0x1021 init 0xFFFF).
- «Обрыв» = в файле меньше байт, чем len говорит, или crc не сошёлся
  на последней записи.
- Снапшот пишется только после успешного чтения журнала.
