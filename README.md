Двести заданий в духе Advent of Code — но вместо рождественских эльфов тут
**нетраннеры, корпоративные ICE-системы и неоновые улицы Аркполиса**. Каждая
миссия — маленькая программа на Go: чтение бинарных файлов, сокеты и сети,
TUI-интерфейсы, криптография, файловые системы, реверс-инжиниринг.

Миссия — это заготовка с двумя функциями `Part1()` и `Part2()`, которые нужно
реализовать так, чтобы тест совпал с эталонным выводом (`data/NNN/expected.txt`).

## Дисклеймер

Этот проект бесстыжим образом навайбкожен. Во-первых, хотелось проверить возможности
опенкода, во-вторых, точность или какая-то ответственность тут не предполагается,
это проект чисто для самообучения, если что не так - я поправлю. По крайней мере, одно
хорошее применение вайбкода есть - не делать программистов тупее, а делать самообучение
интереснее. Если вы не имеете ничего против - добро пожаловать!

## Требования

- Go **1.26+**
- Linux / macOS / Windows (терминал с поддержкой ANSI для TUI)
- Никаких внешних зависимостей — только стандартная библиотека

## Быстрый старт

```bash
git clone <url-репозитория> neon-grid
cd neon-grid

# Эталонные алгоритмы — всегда зелёные
go test ./sol/...

# Прогнать решение конкретной миссии (пока упадёт с TODO — так и задумано)
go run ./solutions/001-pervyi-dzhek-in/

# Проверить миссию тестом
go test ./solutions/001-pervyi-dzhek-in/
```

## Как решать миссию

1. Прочитай миссию: `tasks/NNN-slug.md` — там история и точное техническое задание
2. Открой `solutions/NNN-slug/solution.go` — сигнатуры `Part1()` и `Part2()` ждут тебя
3. Реализуй функции так, чтобы `go test ./solutions/NNN-slug/` стал зелёным
4. Части 1 и 2 сверяются с `data/NNN/expected.txt` независимо — можно сдавать по одной

Можно запустить решение вручную:

```bash
go run ./solutions/001-pervyi-dzhek-in/
```

> **Важно:** `go test ./solutions/...` падает на всех миссиях — так задумано.
> Все заготовки бросают `panic("TODO")`, пока ты их не реализуешь. Зелёный тест
> по одной миссии означает, что она решена.

### Немного про данные

- `data/NNN/expected.txt` — эталон: `часть1` + `=== PART 2 ===` + `часть2`
- Часть данных сгенерирована скриптами, часть написана вручную
- 50 миссий пока без данных (041–080 и некоторые из финальных арок): их тесты
  падают на чтении `expected.txt` ещё до вызова твоих функций. Чтобы решить такую
  миссию, нужно сначала создать `data/NNN/expected.txt`

## Структура проекта

```text
neon-grid/
├── data/NNN/              # входные файлы и expected.txt (150 миссий)
├── sol/                   # эталонные реализации алгоритмов + тесты
├── solutions/
│   ├── NNN-slug/          # 200 заготовок решений
│   │   ├── solution.go         # Part1()/Part2()/main() — сюда пишется код
│   │   └── solution_test.go    # сверяет вывод с expected.txt
│   └── kit/               # хелперы тестов (чтение данных, expected)
└── tasks/NNN-slug.md      # 200 описаний миссий (литературные + технические)
```

**Форматы файлов (011–020)** — BMP, PNG, WAV, NES ROM, CGA, стеганография

**Криптография (021–030)** — XOR, Цезарь, Виженер, частотный анализ, LFSR, OTP, RSA

**Кодирование и сжатие (031–040)** — Base64, RLE, Хаффман, LZW, LZ77, CRC32, битовые потоки,

**Сокеты и сети, база (041–050)** — TCP, echo, HTTP, DNS, чат, FTP, WebSocket, сканер, прокси,
баннеры

**Сети, глубокий уровень (051–060)** — UDP, ICMP, сниффер, NAT, relay, ARQ, gossip, маршрутизация,
ботнет, VNC

**TUI-интерфейсы (061–070)** — прогресс-бары, змейка, морской бой, рисование, монитор, скринсейвер,
квест, браузер, редактор, matrix-rain

**Параллельность (071–080)** — чат, worker pool, async-сканер, race, балансир, планировщик,

**Файловые системы и форензика (081–090)** — FAT12, ELF, PE, MBR, file carving, WAL, RAID5, tar+gz,
бэкапы, расследование

**Мультимедиа и сигналы (091–100)** — WAV, модуляция, GIF, ASCII-art, палитры, аудио-стега, FSK,
QR-код, видео-RLE, сжатие волн

**Реверс-инжиниринг (101–110)** — строки, дизассемблер, crackme, протоколы, патчинг, symtab,

**Финальный взлом (111–120)** — ICE, транзакции, ключи, туннель, руткит, логи, ботнет, МЕРКУРИЙ,

**После финала (121–130)** — CPU-эмулятор, Диффи-Хеллман, БПФ/DTMF, консенсус, GIF-энкодер,

## Досье

**Зен** — наставник, бывший «чистильщик» Омега-Дайн. Говорит редко, но каждое слово — инструкция.
Его чай всегда остывший.

**Дон** — владелец «Гаража», бывший системный инженер. Верит только в то, что можно починить
паяльником.

**CROW** — инфоброкер из «Вороньего гнезда». Платит за шум, продаёт сигнал. Появляется бесшумно.

**Син** — девочка-медиум, слышит Сетку. Говорит о машинах так, будто они живые. Возможно, так и
есть.

**Крем** — барыга с барахолки нижних уровней. Торгует железом, прошивками и слухами. Не любит, когда
его обманывают.

**Прах** — отставной корпоративный «уборщик». Знает протоколы, замки и следы. Помнит, как выглядит
чистая работа.

**МЕРКУРИЙ** — старый ИИ Сетки. Спал десять лет. Теперь считает шаги.

**Чёрный Кот** — кот Дона. Спит на клавиатурах и знает все пароли, но не говорит.

## Разработчикам

- `go build ./... && go vet ./...` — проект всегда должен собираться чисто
- `sol/` — эталонные алгоритмы
- Миссии 131–200 построены «генератор-вперёд»: ожидаемый вывод определяет
  симуляция в генераторе, а текст задачи (`tasks/NNN-slug.md`) фиксирует точный
  алгоритм для игрока (тай-брейки, округления, форматы). Меняешь семантику —
  меняй и текст задачи
- Все описания миссий — литературные интро + техническая часть; при правках
  старайся сохранять оба слоя
